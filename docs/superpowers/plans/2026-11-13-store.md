# 存储 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供一份不碰微信的仓库，让打卡和结算用同一套单据读写。

**Architecture:** `app/types.ts` 放下表字段。`app/store.ts` 导出 `Store` 接口和 `createMemoryStore()`。云数据库适配器留到微信接入计划，必须实现同一个接口。

**Tech Stack:** TypeScript，Node 24 的 `node --test`。不新增运行时依赖。

**Spec:** `docs/agent/ARCHITECTURE.md` 的数据流和数据字段。

## Global Constraints

- `subjectType` 只有 `'personal'`。`subjectId` 等于 `userId`。
- `meal_records.status` 只有 `'checked_in' | 'exempt'`。没有 `open`。漏餐不写记录。
- `photos` 是字符串数组，第 0 张是主图。
- `settlement_jobs.status` 是 `'pending' | 'waiting_review' | 'manual_review' | 'settled'`。
- 同一餐的结算结果只有一行。
- `domain/` 不 import `app/`。

## Review Focus

- 定时扫描会不会把已挂起或已结算的任务再捞出来。测试放在任务 2。
- 同一用户、同一天、同一餐写入第二条餐次记录会不会变成两行。测试放在任务 1。

### Task 1: 单据类型和内存仓库

**Files:**
- Create: `app/types.ts`
- Create: `app/store.ts`
- Test: `test/store.test.ts`

**Interfaces:**
- Consumes: `MealType`、`RecordedStatus`、`MealReview`、`JobStatus`，来自 `domain/index.ts`
- Produces:
  - `MealRecordDoc`: `{ userId, date, meal, status, checkinAt, photos, review, hidden }`
  - `SettlementJobDoc`: `{ subjectType: 'personal', subjectId, date, meal, windowEndAt, status }`
  - `SettlementDoc`: `{ subjectType: 'personal', subjectId, date, meal, outcome: 'fed' | 'starved', hungerBefore, hungerAfter }`
  - `UserDoc`: `{ userId, nickname, timeZone, meals, pendingMeals, stapleLeft, stapleMonth, cooldownUntil, adoptedOn, diedOn }`
  - `PetDoc`: `{ userId, hunger, alive, adoptedOn, endedOn, companyDays, mealsEaten }`
  - `createMemoryStore(): Store`
  - `Store` 方法：`getUser` `saveUser` `getPet` `savePet` `getRecord` `saveRecord` `deleteRecord` `listRecords` `getJob` `saveJob` `listPendingJobs` `getSettlement` `saveSettlement`

### Task 2: 只扫描待执行且窗口已过的任务

**Interfaces:**

- Produces: 同一签名。返回的每条都满足 `status === 'pending'` 且 `windowEndAt <= nowIso`。

- [ ] **Step 1: Write the failing test**

```js
test('pending scan skips held and future jobs', async () => {
  const now = '2026-11-13T04:00:00.000Z'
  const store = createMemoryStore()
  await store.saveJob({ subjectType: 'personal', subjectId: 'u', date: '2026-11-13', meal: 'breakfast', windowEndAt: now, status: 'pending' })
  await store.saveJob({ subjectType: 'personal', subjectId: 'u', date: '2026-11-13', meal: 'lunch', windowEndAt: now, status: 'waiting_review' })

  const due = await store.listPendingJobs(now)
  assert.deepEqual(due.map((job) => job.meal), ['breakfast'])
})
```
