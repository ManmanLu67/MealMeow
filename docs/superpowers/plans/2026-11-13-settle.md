# 结算 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 窗口结束后，按餐次记录的最终状态和审核终态结算一次。没有终态时宠物不变。

**Architecture:** `app/settle.ts` 读 `listPendingJobs`，对每条任务调用已有的 `settleStep` 和 `evaluateFeeding`。饥饿变化只调用 `nextHunger`。审核回调不直接改宠物，而是把终态写回记录后再走同一条结算函数。

**Tech Stack:** TypeScript，`node --test`。不调用微信内容安全接口；测试直接写入 `review`。

**Spec:** `docs/agent/ARCHITECTURE.md` 的审核和结算。

## Global Constraints

- 扫描条件是 `windowEndAt` 已到且 `status === 'pending'`。
- 审核通过：`fed`，按档恢复。驳回或没有记录：`starved`，饥饿 +1。
- `review === 'pending'` 且未到截止时间：任务改为 `waiting_review`，饥饿不变。
- 到达 `reviewDeadline` 仍无结果：任务改为 `manual_review`，饥饿不变。不自动通过，不自动驳回。
- 截止时间是窗口结束后 2 小时，用 `REVIEW_WAIT_MS`。
- 已有 `settlements` 行的餐次不再写第二次，饥饿不再变。
- `pets.alive === false` 或没有宠物时，可以写结算结果，但不改饥饿值。
- `subjectType: 'group'` 不在这里实现。`evaluateFeeding('group', ...)` 保持抛错。

## Review Focus

- 没有餐次记录的待执行任务仍然挨饿。测试放在任务 1。
- 审核挂起超过 2 小时后宠物饥饿值与结算前相同。测试放在任务 1。
- 同一次通过结算跑两遍，饥饿值只变一次。测试放在任务 2。

- [ ] **Step 1: Write the failing test**

```js
test('a missing record starves and a pending review freezes', async () => {
  const end = new Date('2026-11-13T04:00:00.000Z')
  const store = createMemoryStore()
  await store.savePet({ userId: 'u', hunger: 4, alive: true, adoptedOn: '2026-11-01', endedOn: null, companyDays: 1, mealsEaten: 0 })
  await store.saveJob({ subjectType: 'personal', subjectId: 'u', date: '2026-11-13', meal: 'breakfast', windowEndAt: end.toISOString(), status: 'pending' })
  await store.saveJob({ subjectType: 'personal', subjectId: 'u', date: '2026-11-13', meal: 'lunch', windowEndAt: end.toISOString(), status: 'pending' })
  await store.saveRecord({ userId: 'u', date: '2026-11-13', meal: 'lunch', status: 'checked_in', checkinAt: end.toISOString(), photos: ['a'], review: 'pending', hidden: false })
  const first = await runDueJobs(store, end)
  assert.equal((await store.getPet('u')).hunger, 5)
  assert.equal((await store.getJob('u', '2026-11-13', 'lunch')).status, 'waiting_review')
  const later = new Date(end.getTime() + 2 * 60 * 60 * 1000)
  await store.saveJob({ ...(await store.getJob('u', '2026-11-13', 'lunch')), status: 'pending' })
  await runDueJobs(store, later)
  assert.equal((await store.getPet('u')).hunger, 5)
  assert.equal((await store.getJob('u', '2026-11-13', 'lunch')).status, 'manual_review')
  assert.equal(first.settled, 1)
  assert.equal(first.frozen, 1)
})
```

### Task 2: 审核终态只结算一次

**Files:**
- Modify: `app/settle.ts`
- Test: `test/settle-run.test.ts`

**Interfaces:**
- Consumes: `runDueJobs`
- Produces: `applyReview(store, caller: { userId: string }, input: { date: string, meal: MealType, review: 'passed' | 'rejected' }, now: Date): Promise<{ ok: true } | { ok: false, error: string }>`

- [ ] **Step 1: Write the failing test**

```js
test('passing a review feeds once', async () => {
  const end = new Date('2026-11-13T04:00:00.000Z')
  const store = storeWithHeldLunch(end, 8)
  await applyReview(store, { userId: 'u' }, { date: '2026-11-13', meal: 'lunch', review: 'passed' }, end)
  assert.equal((await store.getPet('u')).hunger, 5)
  await applyReview(store, { userId: 'u' }, { date: '2026-11-13', meal: 'lunch', review: 'passed' }, end)
  assert.equal((await store.getPet('u')).hunger, 5)
  assert.equal((await store.getSettlement('u', '2026-11-13', 'lunch')).outcome, 'fed')
})
```

另加一条：`rejected` 把记录删掉或不再当作 `checked_in`，饥饿从 8 变为 9，第二次仍是 9。

- [ ] **Step 2: Run test to verify it fails**

Run: `node --test test/settle-run.test.ts`
Expected: FAIL，`applyReview` 不存在。

- [ ] **Step 3: Implement `applyReview`**

只接受任务状态为 `waiting_review` 或 `manual_review`。通过则把 `review` 写成 `'passed'` 并把任务改回 `pending` 后调用 `runDueJobs`。驳回则删除记录，任务改回 `pending`，再调用 `runDueJobs`。已是 `settled` 时返回 `{ ok: false, error: 'already_settled' }`。

Run: `node --test test/settle-run.test.ts`
Expected: PASS
