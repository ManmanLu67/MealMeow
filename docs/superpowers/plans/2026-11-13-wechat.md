# 微信接入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让小程序页面和两个云函数调用已经测过的命令，不在云函数里再写一套饥饿规则。补上前四份计划留下的缺口：云数据库的 `Store` 适配器、用户和时区同步、照片提交内容安全并接收回调。

**Architecture:** 安装开发依赖 `typescript`，把 `domain/` 和 `app/` 编译到 `cloudfunctions/lib/`。该目录忽略，不入库。`cloudfunctions/api/index.js` 和 `cloudfunctions/settle/index.js` 只做参数校验并调用编译结果。云数据库适配器实现同一个 `Store` 接口，放在 `adapters/cloud/cloud-store.ts`，用一份可注入的数据库客户端，测试时传内存假实现。云函数入口只做三件事：取登录用户、调用 `app/handle.ts` 的 `handle`、返回结果。以后做手机 App 时，复用 `app/` 和 `domain/`，只换适配器和入口。页面把读模型绑到已有的 wxml 上。

**Tech Stack:** 微信云开发，云函数 CommonJS，TypeScript 编译。内容安全这一份只留回调入口和提交函数，不在测试里请求微信。

**Spec:** `docs/agent/ARCHITECTURE.md` 的组件和边界。规则补充见 `docs/agent/decisions/ADR-0002-settlement-freeze-and-review-rules.md`。页面外观已锁定，以 `miniprogram/` 现有页面为准，本计划不改界面。

## Global Constraints

- 云函数不 import TypeScript 源文件。
- `cloudfunctions/lib/` 写入 `.gitignore`。
- 页面动作有 `sync`、`home`、`checkin`、`exempt`、`gallery`、`adopt`、`saveMeals`、`deleteCheckin`。调用者 ID 取自云函数登录态，不接受事件体里的 `userId`。
- `sync` 接收设备当前时区并调用 `syncUser`。页面每次进入首页调用一次。服务端不用服务器时区。
- 定时器保持 `0 * * * * * *`，调用 `runDueJobs`。
- 不新增云函数，不建小组集合，不做抠图。
- 云数据库适配器必须实现 `Store` 的全部方法，包括 `runExclusive`、`listUserIds`、`listFrozenJobs`。`runExclusive` 用事务或锁文档，同一用户的写命令不交错。
- `project.config.json` 不入库，里面是本机 AppID。可提交的示例是 `project.example.config`。`project.private.config.json` 由开发者工具本机生成，不入库。`wx.cloud.init` 的 `env` 不写进仓库。
- 微信开发者工具里的点击本计划写入手工检查，不冒充 `node --test` 已通过。

## Review Focus

- 事件体里带了另一个 `userId` 时，读写的仍是登录用户。测试放在任务 3。
- 页面把 `review: 'passed'` 塞进事件体时不能结算。测试放在任务 3。
- 编译产物被误提交。任务 1 检查 `git status` 不出现 `cloudfunctions/lib/`。
- 云数据库适配器与内存实现行为一致。任务 2 用同一套 `Store` 测试跑两遍。
- 回调只改对应照片。旧照片的迟到回调被拒绝。测试放在任务 4。
