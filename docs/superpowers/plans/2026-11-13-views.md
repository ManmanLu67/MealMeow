# 页面读模型 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 算出首页、图鉴和领养页要显示的数据。页面以后只渲染这些结果。

**Architecture:** `app/views.ts` 读取 `Store`，调用 `domain/` 里已经存在的胶囊、红点、宠物区和连续天数函数。不写库。

**Tech Stack:** TypeScript，`node --test`。

**Spec:** `docs/agent/ARCHITECTURE.md` 的页面和范围、连续天数。页面结构以 `D:\Project\任务规划\吃饭喵\页面设计.md` 为准。

## Global Constraints

- 首页宠物区只用 `homePetView` 的 `'pasture' | 'living' | 'memorial'`。
- 活着时主视图只有 `PET_BAND_TEXT` 的状态词，没有饥饿数字。纪念页才带陪伴天数、共吃餐数、冷却剩余天数。
- 红点只用 `homeBadge`。审核未完成不是红点。
- 图鉴连续天数只用 `personalStreak`。`hidden === true` 的记录不出现在三格里。
- 冷却中 `canAdopt` 为 false。冷却结束且宠物已死时，首页回到 `'pasture'`。
- 不新增 `/pet` 路由。

## Review Focus

- 先打卡的人死亡后，图鉴天数是减去宠物重合天数，不是 0。测试放在任务 2。
- 窗口内已打卡但审核仍是 `pending` 时，红点为 false，宠物区仍是结算前的状态词。测试放在任务 1。
