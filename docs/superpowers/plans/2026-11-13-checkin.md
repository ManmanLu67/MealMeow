# 打卡与饭点 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把用户同步、饭点、完成打卡、应急口粮和删除写成命令。这些命令不改宠物饥饿值。

**Architecture:** `app/user.ts` 建用户并按设备时区更新。`app/schedule.ts` 补结算任务，是三个入口共用的一份逻辑。`app/checkin.ts` 接收 `Store` 和调用者。窗口、饭点间隔、口粮资格沿用 `domain/`。写命令都走 `store.runExclusive(userId, ...)`。

**Tech Stack:** TypeScript，`node --test`。调用 `domain/index.ts` 和 `app/ports.ts`。测试用 `adapters/memory/memory-store.ts` 的内存实现。

**Spec:** `docs/agent/ARCHITECTURE.md` 的打卡、审核、页面和范围。规则补充见 `docs/agent/decisions/ADR-0002-settlement-freeze-and-review-rules.md`。

## Global Constraints

- 选图不写库。`finishCheckin` 才写 `meal_records`。
- 照片至少一张。`photos[0]` 是主图。`review` 初始为 `'pending'`，`photoReviews` 每张照片一项，都是 `'pending'`。
- 饭点第一次保存也从下一个逻辑日生效。今天不产生新窗口。
- 再次保存饭点前，先把已经到生效日的 `pendingMeals` 并入 `meals`，再放新的待生效饭点。否则连改两天会丢掉第一次。
- 相邻饭点少于 2 小时拒绝，恰好 2 小时允许。饭点不能落在 03:01 到 04:59，窗口不能跨过逻辑日界线。
- 结算任务不只在保存饭点时建。`syncUser`、`saveMeals`、`finishCheckin`、`useStaple` 和定时器都补当天和次日的任务，只补缺。改饭点和换时区时刷新仍是 `pending` 的窗口，其余状态不动。
- 一餐已有口粮时 `finishCheckin` 拒绝，不覆盖。先删除口粮再打卡。
- 未结算删除调用 `deleteCheckin(false)` 的结果 `'cancel'`，删掉记录。已结算调用 `deleteCheckin(true)`，只把 `hidden` 设为 true。
- 未结算删除时，若任务正挂在 `waiting_review` 或 `manual_review`，放回 `pending` 并立即结算，这一餐按漏餐。
- 未结算删除口粮退回当月额度，但不超过每月额度。已结算后删除不退。
- 口粮资格用 `canUseStaple`。额度每月 2，按 `stapleMonth` 换月后回到 2。
- 命令发现单据上的用户 ID 不等于调用者时抛错，不读写。
- 不调用 `applyMeal`。

## Review Focus

- 打卡成功后饥饿值仍是原数。测试放在任务 3。
- 结算前删除再结算会变成漏餐；结算后删除照片还在库里但 `hidden` 为 true。测试放在任务 4。
- 用别人的 `userId` 写入会被拒绝。测试放在任务 3。
- 连续两天改饭点，14 日的打卡窗口和任务窗口一致。测试放在任务 2。
- 没改过饭点的用户也有任务，漏餐扣饥饿。测试放在任务 1。
- 冻结期间删除打卡，这一餐按漏餐结算，不会卡死。测试放在任务 4。
