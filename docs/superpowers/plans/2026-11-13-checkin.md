# 打卡与饭点 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把饭点、完成打卡、应急口粮和删除写成命令。这些命令不改宠物饥饿值。

**Architecture:** `app/checkin.ts` 接收 `Store` 和调用者。窗口、饭点间隔、口粮资格沿用 `domain/`。结算任务在保存饭点时创建，不在打卡时创建。

**Tech Stack:** TypeScript，`node --test`。调用 `domain/index.ts` 和 `app/store.ts`。

**Spec:** `docs/agent/ARCHITECTURE.md` 的打卡、审核、页面和范围。

## Global Constraints

- 选图不写库。`finishCheckin` 才写 `meal_records`。
- 照片至少一张。`photos[0]` 是主图。`review` 初始为 `'pending'`。
- 饭点第一次保存也从下一个逻辑日生效。今天不产生新窗口。
- 相邻饭点少于 2 小时拒绝，恰好 2 小时允许。
- 未结算删除调用 `deleteCheckin(false)` 的结果 `'cancel'`，删掉记录。已结算调用 `deleteCheckin(true)`，只把 `hidden` 设为 true。
- 口粮资格用 `canUseStaple`。额度每月 2，按 `stapleMonth` 换月后回到 2。
- 命令发现单据上的用户 ID 不等于调用者时抛错，不读写。
- 不调用 `applyMeal`。

## Review Focus

- 打卡成功后饥饿值仍是原数。测试放在任务 2。
- 结算前删除再结算会变成漏餐；结算后删除照片还在库里但 `hidden` 为 true。测试放在任务 3。
- 用别人的 `userId` 写入会被拒绝。测试放在任务 2。
