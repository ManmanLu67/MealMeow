# 本机版 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 小程序在本机完成打卡和宠物结算，不调用云函数。

**Architecture:** 现有 `domain/` 和 `app/` 命令不变义。新增本机 `Store`、把本地打卡立刻标为通过、按逻辑月删照片但留记录，以及一个只给小程序用的 `openLocal` 入口。页面改调这个入口。云函数代码留着不调用。

**Tech Stack:** TypeScript，`node --test`，微信小程序本地缓存和 `FileSystemManager`。

**Spec:** `docs/superpowers/specs/2026-11-23-local-mvp-design.md`

## Global Constraints

- 不删除 `cloudfunctions/`、`adapters/cloud/`、`app/media-check.ts`。
- `domain/`、`app/` 不调用 `wx`，不写 `new Date()` 或 `Date.now()`。时间由调用者传入。
- 不改已锁定页面的布局。新增昵称页，以及「隐私与关于」上的导出、导入。
- 不做小组、跨用户、独立 `/pet`、抠图、订阅消息。
- 不把照片放进 `wx.setStorage`。记录里的 `photos` 只存路径。
- 不改 `project.config.json`、`project.private.config.json`。
- 计划里的 Commit 步骤先不要执行，除非用户在当次明确要求提交。
- 压图只用 `wx.compressImage`，`quality` 为 `20`。
- 逻辑月沿用 `stapleMonth`：该时区每月 1 日 04:00 换月。保留本月和上月的照片。
- 导出不嵌入图片字节。导入是整份替换。坏文件不写存储。

## Review Focus

- 窗口已经结束才打卡：仍算吃到，不能先被结算成漏餐。Task 4 的测试覆盖。
- 导入文件不是这份备份：原记录还在。Task 5 的测试覆盖。
- 上上个月的打卡：照片路径被清掉，连续天数和图鉴绿格还在，格子不是漏餐的虚线空格。Task 4 的测试覆盖。
- 压缩或保存文件失败：不调用打卡。Task 7 的页面顺序覆盖，微信运行时没有单测。
- 删文件失败：打卡记录还在，只是路径还指向一个打不开的文件。Task 4 只返回路径，不在命令里删文件。

`acceptPendingPhotos`：窗口内打卡后 `review` 仍是 `pending`。调用之后该餐每张 `photoReviews` 都是 `passed`，`review` 是 `passed`。同一时刻零食的新照片也是 `passed`。然后把 `now` 拨到窗口结束之后调用 `runDueJobs`，宠物饥饿下降（吃到），不是冻结。

图鉴：`galleryView(..., '2026-09-30')` 的三餐 `face` 是 `kept`，`photo` 是 `null`。

### Task 6: 本机入口

**Files:**
- Create: `app/local-session.ts`
- Test: `test/local-session.test.ts`

**Interfaces:**
- Consumes: `handle`，`acceptPendingPhotos`，`clearExpiredPhotos`，`runDueJobs`，`exportBackup`，`importBackup`
- Produces: `openLocal(store: Store, caller: Caller, now: Date, raw: unknown, fileExists?: (path: string) => boolean): Promise<LocalResponse>`
- `LocalResponse = { ok: true; data?: unknown; droppedPhotos: string[] } | { ok: false; error: string }`
- 成功时总是带 `droppedPhotos`。这一轮没删照片就是空数组。
- `fileExists` 返回 false 的路径只从这次读模型里拿掉，存储里的路径不动。不传就当作文件都在。

- [ ] **Step 1: Write the failing test**

`{ action: 'checkin', meal: 'lunch', photos: ['p'] }` 在窗口内：返回成功，记录已是 `passed`。

同一请求若 `now` 已过窗口结束：返回成功，并且 `runDueJobs` 之后这一餐是吃到，不是漏餐。调用顺序是先打卡、再标通过、再结算。

`{ action: 'home' }` 会先结算已到期的餐，再清掉过期照片路径，然后返回首页。返回的 `droppedPhotos` 是被清掉的路径。

`fileExists` 对某张今日照片返回 false 时，首页读模型不带这张图，`getRecord` 里的路径还在。

没有用户时 `{ action: 'home' }` 返回 `no_user`，不写结算。

`{ action: 'export' }` 返回 `LocalBackup`。`{ action: 'import', backup }` 走 `importBackup`。

- [ ] **Step 2: Run test to verify it fails**

Run: `node --test test/local-session.test.ts`

Expected: FAIL

- [ ] **Step 3: Implement `openLocal`**

`checkin` 和 `snack`：`handle` 成功后 `acceptPendingPhotos`，然后 `runDueJobs`。`droppedPhotos` 为 `[]`。其他动作：没有用户就直接 `handle`。有用户时先 `runDueJobs`，再 `clearExpiredPhotos`，然后 `handle`。返回前按 `fileExists` 把读模型里不存在的照片拿掉。`export` 和 `import` 不交给 `handle`。
