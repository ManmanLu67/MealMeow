# ADR-0001: 开发骨架和规则收口

- Status: accepted
- Date: 2026-11-13

## Context

全局规则要求新项目用 agent-hub 的项目模板：短的 `AGENTS.md`、`CLAUDE.md`、`docs/agent/` 下的现状和架构说明。仓库原先只有一份写满产品规则的 `AGENTS.md`，没有这套骨架。规划目录里还有几句和已定规则相反的话。

## Decision

- `AGENTS.md` 只保留模板里的工作约定。产品规则写在 `docs/agent/ARCHITECTURE.md`。
- 饥饿按档恢复，策略不返回增减。
- 打卡写入事实。结算只由 `settlement_jobs` 在窗口结束且审核终态之后驱动。
- 审核未回或超时待复核时，宠物冻结。不自动通过，不自动驳回。
- 连续天数分先领养和先打卡。死亡不清空全部个人天数，也不清空图鉴。
- 没有独立宠物页。打卡以「完成打卡」写入。一餐多张，首张是主图。
- 抠图、涂抹、餐盘不在本轮。原图的日界线删除等抠图上线后再按较晚时点执行。
- 小组不在本版本实现。
- 《吃饭打卡小程序：产品与规则设计文档.md》停用。

## Consequences

正式做云函数之前先看 `ARCHITECTURE.md`。规划原文若再被改回旧句，以本决定和 `ARCHITECTURE.md` 为准。

## Rejected alternatives

- 把产品规则继续全部堆在 `AGENTS.md`。全局模板要求这份文件保持短，事实放在 `docs/agent/`。
- 饥饿用固定 +1 / -1。和个人版本的按档恢复不是同一套，策略里也不再返回 `hungerDelta`。
- 窗口一结束就结算。审核未回时会误伤或绕过内容安全。
- 死亡把个人连续天数直接写成 0。先打卡的人还要保留减去宠物时间之后的天数。
